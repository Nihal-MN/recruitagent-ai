# RecruitAgent AI v0.1.0

**A human-in-the-loop recruiting operations agent** — tool calling, approvals, MCP, and grounded recruiter workflows. Runs with **zero API keys**.

## Highlights

- **10 tools** (6 reads · 2 generations · 2 controlled writes) with strict Pydantic contracts — the agent can't call anything else.
- **Approvals enforced in the backend**: pipeline moves and notes become proposals; execution happens only after a human decides — **exactly once**, with replay protection.
- **Grounded answers**: deterministic explainable matching with quoted evidence; no invented entities; "unknown" is a first-class answer.
- **Prompt-injection resistant**: resumes, JDs and notes are untrusted data (tested across all three).
- **MCP server**: six read tools plus a proposal-only write — write execution is impossible over MCP.
- **23-scenario eval suite** + 74 backend tests, hermetic in CI (no network, no key).
- **Two interchangeable providers**: a deterministic demo agent (keyless) and OpenAI tool calling (`AI_PROVIDER=auto`).

## Quick start

```bash
git clone https://github.com/Nihal-MN/recruitagent-ai.git
cd recruitagent-ai
cp .env.example .env
docker compose up --build -d
docker compose exec api python -m app.seed
# open http://localhost:3000
```

Then try: *"Find candidates for the Senior Backend Engineer role"* → *"Why does this candidate match?"* → *"Move this candidate to INTERVIEW"* (approve it in **Approvals**) → *"Add a note: …"*.

## Honest notes

- Solo portfolio project. Local demo — **no auth by design**; do not expose with real candidate data (see SECURITY.md).
- The OpenAI path is implemented against the current API and stub-tested in CI; it is not live-tested here (no key). `/health` always reports which provider actually ran.
- Demo data is fully synthetic (20 candidates, 5 jobs, notes, pipeline states).
